# 常见问题与边界

## 会不会把上下文烧掉？

不会。常驻的只有 T1（建议 ≤200 行）和一段约 4 行的使用约定；T2/T3 只在检索命中时读取**片段**，
且超过 600 KB 的文件只按文件名命中、不读全文。`memory_index` 用极低成本先看「有什么记忆」再决定是否深入。

## 开新会话时，模型怎么知道要读简报？

三种触发方式，按环境任选：

1. **钩子**：Claude Code 的 `SessionStart` 钩子会直接把 T1 简报并入上下文（装了插件就生效）；
2. **宿主约定**：把 `ltm guide` 的输出贴进 `AGENTS.md`（Codex）或 `CLAUDE.md`，模型每轮都能看到；
3. **用户触发**：用户说「接着上次」这类话时，本技能会被加载，按 SKILL.md 的流程先读简报。

## 记忆里没有相关记录，但我觉得以前修过？

顺序是：先用用户**另一个说法**再搜一次；仍然没有就明确说「记忆里没有」。
**不要**编造一条看起来合理的历史修复记录 —— 这是这套系统里最贵的错误，
因为编造的内容会通过 `memory_write` 变成「历史事实」，污染后续所有会话。

## 同一个问题又出现了，新建文件还是续写？

**续写同一个文件。** `memory_write` 检测到文件已存在会自动追加 `## 第 N 条记录 · 时间戳`。
新建文件会让检索碎成一片，历史演进（哪一版方案失效了）也就丢了。

## 分类拿不准怎么办？

大类只有四个：`修复bug` / `新功能` / `疑问咨询` / `回顾重构`。拿不准就放 `其他/`，
但**不要**为了「整齐」把一次会话拆到多个文件 —— 宁可一个文件里五段记录。

## 支持多个项目吗？

每个项目根各自一份 T1-T4 与自己的标记，天然隔离。跨项目检索不支持（也不建议：
把另一个项目的上下文拉进来是幻觉来源）。

## 能放进 Git 吗？

可以。建议 T1/T3 入库，T2 视体积与隐私决定。两个标记文件可以忽略。

## Windows 上有什么坑？

- 文件名禁用字符 `<>:"/\|?*` 会被替换；`->` 会变成 `→`（所以 T2 周文件名里是箭头）；
- 长正文不要直接塞命令行（约 32k 上限），用 `--content-file <路径>`；
- 路径分隔符统一用 `/` 或 `\` 都可以，工具内部会规范化。

## 检索命中了但不准？

BM25 是确定性关键词检索，不是语义检索。提升命中率的正确做法：

- 写入时在 `tags` 里把**用户的原话**一起写上（口语说法、错别字、简称都写上）；
- 标题用「问题点」而不是「会话日期」；
- 真正的语义检索不在本系统的目标里 —— 它要的是可预测、零依赖、零联网。

## 记忆根目录放在哪？

默认就是项目根。想放子目录（例如 `memory/`）时，用 `LTM_PROJECT_ROOT` 指向它，
或在调用时传 `--root` / `project_root`。注意：一旦选定就别频繁换，
否则会出现两份 T1，模型读到旧的那份反而更糟。

## 卸载/退出

删掉技能/插件目录即可，**项目里的 T1-T4 不受影响**。
如果确定不再需要记忆：先归档（`memory_log`），再手动删除四个目录与两个标记文件。
