# 目录与双布局

## 一份记忆长什么样

```
<项目根>/
├─ .longterm-memory.json          # 标记（Claude Code 侧命名）
├─ .dsh-longterm.json             # 标记（DSH 侧命名，内容里带真实 layout）
├─ T1-交接/
│  ├─ 项目进度交接.md              # 当前状态 / 下一步 / 关键约束（≤200 行）
│  ├─ 当前活跃问题.md              # 进行中 / 已解决待验证 / 阻塞
│  └─ 交接文档/
│     ├─ 项目结构.md               # init/adopt 时自动扫描生成
│     ├─ 用户习惯.md
│     ├─ 用户强调.md
│     └─ AI经常踩的坑.md           # 现象 → 根因 → 硬规则
├─ T2-全日志/
│  └─ 第42周-2026年10月12日→2026年10月18日.md    # 一周一文件，AI 不主动读
├─ T3-分类整理/
│  └─ 修复bug/游戏机制/NPC相关问题/NPC穿模.md      # 大类/模块/问题点，同一问题续写同一文件
└─ T4-项目/                        # 代码或资源；记忆工具只列不读
```

## 双布局：cc 与 dsh

| 布局 | 目录名 | 标记文件 | 谁在用 |
| --- | --- | --- | --- |
| `cc` | `T1-交接` / `T2-全日志` / `T3-分类整理` / `T4-项目` | `.longterm-memory.json` | 本技能、Claude Code 插件、Codex、Hermes 默认 |
| `dsh` | `T1-交接文件夹` / `T2-全日志记录文件夹` / `T3-日志分级整理文件夹` / `T4-项目目录文件夹` | `.dsh-longterm.json` | DSH 插件（`dsh-longterm-memory`） |

差别只有目录名与子目录 `交接文档/` vs `交接文档文件夹/`。**文件格式与语义完全一致。**

### 为什么要两套

DSH 插件先落地（0.2.0），目录名带「文件夹」后缀；Claude Code 侧沿用更短的名字。
两边都要能读同一份记忆，所以工具侧做了识别，而不是逼用户迁移数据。

### 识别规则（`detectLayout`）

1. 读已存在的标记文件里的 `layout` 字段 —— **以内容为准**，因为 `init` 默认**同时写两个标记**；
2. 没有标记就看根目录下 `T1-*` 目录的名字（`T1-交接` vs `T1-交接文件夹`）；
3. 都没有就按默认布局新建（`cc`）。

`memory_init` / `ltm init` 默认写两个标记（`--markers both`），这样**四个宿主打开同一项目都能认出它**。
想只写一个：`--markers cc` 或 `--markers dsh`。

### 新建项目用哪套

- 新项目、主要用 Claude Code / Codex / Hermes → 默认 `cc`，最省事。
- 项目已经在 DSH 里跑过（根目录有 `T1-交接文件夹/`）→ 什么都不用改，工具会自动认成 `dsh`。
- 想强制指定：`ltm init --layout dsh`。

## 两个标记同时存在，会不会乱

不会，但要知道取舍：

- 两个标记里写的是**同一个真实 layout**（不是各自的名字），所以识别结果一致；
- 代价是项目根多一个小 JSON 文件。不想要就 `--markers` 单选，或在 `.gitignore` 里忽略它们
  （本仓库的 `.gitignore` 已包含）。

## 和代码仓库的关系

记忆目录和代码放在同一个仓库里是可以的（推荐），但要注意：

- T1/T3 是**给模型看的**，应当进版本库（这是团队共享项目上下文的方式）；
- T2 是原始日志，通常体积大且含会话细节，是否入库看团队习惯；
- `.gitignore` 里至少忽略 `node_modules`、`dist` 这类目录，避免 `memory_adopt` 扫描时把噪声写进 `项目结构.md`。
