现在做长期记忆归档，按顺序执行：

1. **写 T3（结构化知识）**：调用 `memory_write`，`category` 形如 `修复bug/游戏机制/NPC相关问题`，大类只取
   `修复bug` / `新功能` / `疑问咨询` / `回顾重构`。正文建议固定五段：**现象 / 根因 / 改了什么 / 怎么验证 / 遗留风险**。
   同一个问题反复出现时**续写同一个文件**（工具会自动编「第 N 条记录」），不要新建文件。
2. **追加 T2（原始日志）**：调用 `memory_log`，写本轮做了什么、改了哪些文件、有哪些结论，一到三段即可。
3. **更新 T1**：用 `memory_write` 覆盖
   - `T1-交接/项目进度交接.md`：只留「当前状态 / 下一步 / 关键约束」，控制在 200 行内；
   - `T1-交接/当前活跃问题.md`：只留正在处理中的；已解决的移出。
4. **踩坑与偏好**：如果本轮用户纠正了你，或同一个错误犯了第二次，追加到
   `T1-交接/交接文档/AI经常踩的坑.md`，格式：现象 → 根因 → 硬规则。
   如果用户表达了新的输出偏好，更新 `用户习惯.md`。

最后用一段话汇报：写了哪些文件、T3 的路径、T1 是否已更新。
